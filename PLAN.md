# MacKit: Plan

A native macOS utility for setting up and tuning a Mac: tweaks, debloating, privacy, app installs, and reusable setup profiles. Built in Swift and SwiftUI, targeting the macOS 27 SDK, designed to look and feel like a first-party Apple app.

Status (2026-11-19): version 0.1.1 is released as an unsigned disk image on GitHub. "Where things stand" below is the current record. Sections 1 to 12 are the original plan, kept as written; where they disagree with "Where things stand", that section wins.

---

## Where things stand

**Built**
- `MacKitCore` engine: a declarative catalog of 412 settings in 18 categories, state reading, change planning, apply with rollback, exact undo from snapshots, JSON history, live-apply signals, and the app installer. The suite has 87 tests in 22 suites: 77 run by default against an in-memory fake of the system and locally built fake apps; the other 10 are opt-in live or real-data checks gated by environment variables (`MACKIT_LIVE`, `MACKIT_LIVE_APPLY`, `MACKIT_LIVE_ADMIN`, `MACKIT_CASKS`, `MACKIT_DUMP`, and others).
- The app: Home (this Mac plus four quick setups), 18 settings pages, search, a review sheet, History with undo, and the store (Discover and Installed).
- A detail page for every setting: the control and the facts about it. There are no preview pictures. Real macOS screenshots were tried twice (2026-11-16 and 17) and removed at the user's request; the capture briefs and import scripts are parked in `Archive/Captures`, the earlier drawn previews in `Archive/DrawnPreviews`.
- Quick setups: Developer, Calm Dock, Power Finder, Clean Captures.
- Live apply (2026-11-17): after saving, the engine sends a `LiveSignal` (`Tweak.liveSignal`, `System/LiveSignals.swift`) so running apps pick the change up, the way System Settings does. Checked on the real Mac with the user's go-ahead, by flipping each setting for a second and restoring it while a separate running app watched (`MACKIT_LIVE_APPLY=1 swift test --filter LiveApplyTests`, or `=glass` for one step): Light/Dark/Auto, accent, Liquid Glass tint, wallpaper tinting, scroll bars, menu bar hiding, keyboard navigation, and pointer size all apply live. Accessibility display options: the change notice reaches running apps, but the value flip wasn't seen because the test tool lacks Full Disk Access to write `com.apple.universalaccess`. Not confirmable: sidebar size, menu bar in full screen, trackpad/mouse/fn keys (`activateSettings -u`; nothing readable changes, even with System Settings' own `MTTGestureBackEnd`), so trackpad keeps its "after logging out" label. Still not live: icon and widget style (`SLSIconAppearanceConfiguration`, enum values unknown), menu bar background (`SLSSetMenuBarUseBlurredAppearance`, second argument unknown), key repeat and pointer speed (IOHID, units unverified), window corners. `_AXSSet…` in libAccessibility does nothing from an ordinary app.
- Sample mode (`-sample 1`) runs every flow without touching real settings.
- App icon, generated by `Tools/make-icon.swift`: a flat PNG set and a layered Liquid Glass icon (`MacKit/AppIcon.icon`). The README wordmark and social preview come from `Tools/make-brand.swift`, set in Allo (`Brand/Allo`, SIL Open Font License). Both scripts reproduce the committed images byte for byte.
- Release pipeline (2026-11-17): `.github/workflows/ci.yml` runs the engine tests and an arm64 Release build side by side on every push, and packs a verified disk image with `Tools/make-dmg.sh`. Pushing a `v*` tag runs `release.yml`, which reuses that run, records build provenance, and publishes a GitHub release with the disk image and its SHA-256. Released: v0.1.0 (2026-11-17) and v0.1.1 (2026-11-18). MIT license.
- v0.1.1: installed apps also get the installed-in-place quarantine flag, so macOS no longer runs them from a read-only translocated copy (their own updaters failed before; found with Discord).

**Design direction (revised after first review)**
The first pass showed raw keys, Terminal commands, and an always-open inspector. It read as a debug tool. The current rules:
1. Native controls. System switches and pop-up menus, not custom ones.
2. Plain language first. Keys and commands appear only when a row is opened or "Show Commands" is clicked in the review.
3. Grouped cards on one calm surface, like System Settings. Glass only on the floating changes bar.
4. Color: icons are monochrome. The accent is the only color, and marks the primary action and pending changes. Store app icons are the one place with richer color. (Setting previews, which once had it, were removed.)

**Decided differently from the original plan**
- Preferences are written through CFPreferences, not by launching `defaults`. The equivalent `defaults` command is still shown on request.
- Administrator changes use the system password prompt (`do shell script … with administrator privileges`). This works unsigned. `SMAppService` needs a signed app, so it waits for a Developer ID.
- Privacy tweaks were first dropped because the keys couldn't be confirmed on macOS 27, then partly returned: the "Privacy & Security" category now has personalized ads, the advertising identifier, Mac Analytics, and crash reporting (`privacy.*`), next to the firewall, guest user, and Touch ID for sudo.
- Touch ID for sudo was first left out, then added (`security.touch-id-sudo`, edits `/etc/pam.d/sudo_local` through the administrator prompt). It has not been confirmed end to end.
- The store installs apps itself from Homebrew Cask's public data and never runs `brew`. `mas` and Homebrew formulae are out.

**Catalog (2026-11-16)**
- 400 settings in 18 categories, up from 40. Sources were Apple docs, man pages, nix-darwin, macos-defaults, and the system binaries on macOS 27.2. Only keys that still exist on 27.2 are in; about 110 dead or unconfirmed keys were left out.
- New engine support: per-Mac (`-currentHost`) preferences, root-owned preference files written through the administrator prompt, command-read settings with a data-driven probe (`Probe`), settings that hide on Macs without the hardware, cautions, and a Full Disk Access gate for apps with protected containers.
- `MACKIT_LIVE=1 swift test --filter LiveProbeTests` reads every setting from the real Mac without changing anything.
- Sliders, text fields, and nested dictionaries (updated 2026-11-17): a setting can take an entered number or line of text (`ValueInput`) and can read/write a leaf inside a nested preference dictionary without disturbing sibling keys (`PreferenceBinding.path`, shown as `PlistBuddy` commands). Twenty numeric settings are sliders (including mouse scroll speed, Dock recent app count, window title icon delay, Calendar hours shown, Xcode page guide column, and Desktop icon/grid/label sizes); computer name, lock screen message, screenshot name, and Safari homepage are text fields; Desktop Icons and Stacks (`DesktopViewSettings`) are in. 412 settings in all, covered by 61 tests across 17 suites at the time.
- State reading & honest effect labels (2026-11-17): companion/device mirror keys (`windows.save-expanded`, `windows.print-expanded`, `safari.develop`, `trackpad.*`, `mouse.magic-secondary`, `region.measurement`), Auto appearance at night (`AppleInterfaceStyle` + `AppleInterfaceStyleSwitchesAutomatically`), and disabled Scroll Zoom no longer misread as `Custom` when macOS writes only one key. Unverified "Right away" labels were audited and fixed (`stage.enabled`, `menubar.live-activities`, and `screenshot.*` now restart `WindowManager`, `ControlCenter`, or `SystemUIServer`; `sound.*`, `spotlight.clipboard*`, `menubar.fullscreen`, `screensaver.start`, `access.*` without live confirmation, and `finder.sidebar-size` now state their real logout or app-relaunch scope), enforced by a catalog test.
- Search, filing, and launch speed (2026-11-17): `Catalog.search` ranks multi-word queries across titles, categories, sections, option labels, preference keys, and common synonyms; misfiled settings (`backup.full-speed`, `appearance.app-nap`, `appearance.recent-documents`, `appearance.auto-quit`, `appearance.versions-debug`, `appearance.control-characters`) were moved to their proper categories; Review and History rows show section context (`Category · Section`). `TweakEngine.states(of:)` runs `@concurrent`, checks Full Disk Access once, and deduplicates shared `Probe` commands in a bounded task group, cutting a full real-Mac read (`LiveProbeTests`) from 2.43 s to 0.073 s.
- Not in the catalog: per-folder Finder view overrides, Mail, and anything macOS blocks (Gatekeeper "Anywhere", charge limit, Bluetooth power).

**Instant apply (2026-11-16)**
- 298 of 412 settings are written the moment they change (`Tweak.appliesInstantly`). The rest still wait for review: anything needing an administrator password, anything with a caution, anything that restarts Finder (that cancels file copies), and typed text.
- Sliders wait 0.45 s after the last movement. Instant changes land in History, grouped when made within two minutes, and undo the same way.
- Quick Setups and "Reset to Defaults" for a whole category always go through review.

**App store (2026-11-16)**
- Discover and Installed pages. The list is Homebrew Cask's public catalog (`formulae.brew.sh/api/cask.json`), filtered to plain apps that run on this Mac: about 3,500. Homebrew itself is not needed and not used.
- `AppInstaller` downloads from the maker's address, checks the SHA-256 when the catalog has one, opens the disk image or archive, marks the app as downloaded, asks macOS to confirm the developer (`spctl`), and only then moves it into Applications. An existing copy goes to the Trash.
- Categories are a hand-sorted list of 204 well-known apps (`StoreCategories.swift`); everything else is under All and search.
- Icons come from a community icon collection, the maker's site, or its GitHub picture, cached on disk, downsampled to 192 px, and held in a bounded `NSCache` with per-card `.task` loading and bounded network concurrency. Installed apps show their real icon. Install failures appear inline on cards and rows, with plain-English `URLError` messages; `Popular Right Now` expands to browse top apps, and `⌘R` reloads the store when viewing it.
- Accessibility and keyboard (2026-11-17): setting rows, app cards, and installed app rows open details via keyboard-focusable buttons without intercepting inline controls, detail pages dismiss on Escape as well as `⌘[`, VoiceOver labels/hints include cautions, admin requirements, and target names on repeated `Undo`/`Get` buttons, `ChangesBar` falls back to a solid bordered surface under Reduce Transparency, and cards/chips/dividers strengthen borders under Increase Contrast.
- Left out: installer packages (Zoom, Teams), command-line tools, fonts, Mac App Store apps, and removing an app's leftover files.
- The automated tests use locally built fake apps (zip and disk image) only. The installer has had light real use on the owner's Mac, which is how the v0.1.1 translocation bug was found.

**Pre-release safety review (2026-11-17)**
- Hardened `AppInstaller` and `CaskCatalog`: rejected malformed cask checksums, path traversal in `bundle.source` and `installedName`, top-level `.app` symlinks, and bundle symlinks escaping the `.app`; enforced `https` on redirects; quarantined downloads before opening so read-only (`0555`) bundles keep `com.apple.quarantine` and verified quarantine before `spctl`; staged and verified multi-bundle updates before replacing `/Applications` with Trash rollback on failure; fixed read-only temp directory cleanup and preflighted `/Applications` write access before downloading.
- Hardened root and system paths: isolated per-change subshells and exit reporting inside `AdministratorPromptRunner` (`PrivilegedBatchScript`) so one failed root command never drops undo snapshots for earlier changes or skips later ones; hardened `security.touch-id-sudo` (`LC_ALL=C`, newline guard, `chmod 444`, safe no-op when `sudo_local` is absent); restored `0644` permissions after root `defaults` writes to direct system plist files (`network.captive-portal`).
- Hardened other-Mac, undo, and live-signal paths: added System Settings' missing `pmset` sleep durations (`3`, `20`, `45`, `90`, `120`, `180` min; `disksleep 1`) so valid Macs don't hide power settings as `.unknown`; gated laptop-only battery/lid settings (`power.lid-closed`, `startup.auto-boot`, `menubar.battery-percentage`, `sound.charging-chime`) on `AppleSmartBattery`; stopped offline icon lookups from writing permanent `.icon.none` markers and expired negative markers after 24 hours; backed up unreadable `history.json` files before saving and made `HistoryRecord` entry decoding forward-compatible; fixed Turkish/Azerbaijani search folding; guarded `setGlassTint` with runtime `NSGlassEffectView.Legibility` layout and tag checks. 75 tests across 19 suites passed at the time.

**Polish pass (2026-11-19)**
- Engine: the installer and the command runner now read a tool's output while it runs, so a tool that prints more than a pipe holds (`xattr -r` on a large read-only app) can't hang an install; out-of-range or infinite stored numbers no longer crash on read or entry; GitHub icon lookup no longer matches hosts like `notgithub.com`. Each has a test.
- App: opening an app from store search results works; Discard Changes moved to ⌥⌘⌫ so ⌘⌫ stays with text fields; Review and Discard are disabled while the review sheet is open; a failed Move to Trash shows an error instead of offering a Retry that reinstalls; Installed shows the load failure instead of "nothing installed"; Quick Setups wait until the Mac has been read. Wording made consistent ("Customized", "Discard" for pending changes).
- Repo: `make-dmg.sh` always detaches its image; added `CONTRIBUTING.md` and a bug report form.
- Suggested, not done: rename the sidebar's "App Store" heading (it suggests the Mac App Store), share one Increase Contrast border helper, confirm before moving an app to the Trash.

**Not done**
- Signing and notarization. There is no Developer ID, so builds are ad-hoc signed and macOS asks for "Open Anyway" on first launch. The bundle ID `dev.mackit.MacKit` is a placeholder and the name is unchecked.
- Most writes are verified only against the fake. Reads were verified on macOS 27.2 (`LiveProbeTests`); the live-apply set above was flipped and restored on a real Mac (`LiveApplyTests`).
- Administrator path: `LiveAdminTests` covers pmset and a root-owned preference file, and the README reports those as tested on a real system. Touch ID for sudo is not confirmed end to end. launchctl sharing services and protected app containers (Full Disk Access) have not been written for real.
- Settings still not applied live: see the Live apply entry above.
- Profiles: import and export (sections 4 and 9) are not built.
- Updates for MacKit itself (Sparkle or similar) are not built; users download new releases by hand.
- Motion was written to the guidelines but only checked in still screenshots.

## 1. Goals and non-goals

**Goals**
- One place to review, apply, and revert system tweaks on a fresh or existing Mac.
- Every change is visible before it happens, explained in plain language, and reversible.
- Install apps in bulk (Homebrew casks and Mac App Store where possible).
- Save a setup as a profile and reapply it on another Mac.
- Feel native: Liquid Glass chrome, correct typography, fluid motion, full accessibility.

**Non-goals (for v1)**
- Not a cleaner or antivirus. No "optimize RAM" buttons with vague promises.
- No one-click "run this shell script from the internet."
- No Windows or Linux.
- No App Store build in v1 (see section 6).

## 2. Platform decisions

| Decision | Choice | Why |
|---|---|---|
| Language | Swift 6 (strict concurrency on) | Data-race safety from day one |
| UI | SwiftUI, with AppKit only where SwiftUI can't reach | Modern, and matches the Liquid Glass design system |
| Minimum OS | **macOS 27** (decided) | Lets us use the new SDK without `#available` branches. Tradeoff: smaller audience. |
| Toolchain | Xcode 27.2, Swift 6.4.2 (already installed on this machine) | Matches the macOS 27.2 SDK |
| Distribution | Unsigned DMG on GitHub Releases for now. Homebrew and other installers later. | No Apple Developer account yet, so signing and notarization wait. System-level tweaks (`defaults`, launchd, `/etc`, `sudo`) don't fit the App Store sandbox |
| Data | JSON files in Application Support. No database. | Small, inspectable, easy to version and share as profiles |
| Tests | Swift Testing, plus snapshot previews | Current standard in the toolchain |

## 3. Design direction

The goal: it should look finished on the first screen. Design decisions come before features.

**Principles**
1. **Content stays calm; chrome gets the glass.** Liquid Glass goes on sidebars, toolbars, floating action bars, and sheets. Tweak lists and text stay on clear, solid-enough surfaces so they stay legible over any wallpaper.
2. **Explain before you touch.** Every tweak shows a one-line plain-English summary, a risk badge, and a "What this changes" disclosure with the exact commands or keys.
3. **Calm motion.** Springs for interactive changes, short eased transitions for state changes. Respect Reduce Motion everywhere.
4. **Native first.** System colors, SF Pro, SF Symbols, system materials. Accent color follows the user's system setting.
5. **Dense where it helps.** Tweak rows are compact and scannable. Setup and onboarding get space and whitespace.

**Design tokens (defined once, in `MacKitUI`)**
- Spacing: 4pt grid (4, 8, 12, 16, 24, 32)
- Radii: aligned with the system window radius so nested corners look concentric
- Type: system text styles only, so Dynamic Type and optical sizing come for free
- Color: semantic roles (`risk.safe`, `risk.caution`, `risk.advanced`) mapped to system colors, with light and dark variants checked

**Glass usage**
- `GlassEffectContainer` groups related glass elements so they blend and morph together.
- `glassEffectID` animates the "Review 12 changes" bar growing from the selection count.
- `glassEffectUnion` merges adjacent controls into one shape.
- Prefer `GlassButtonStyle` and `GlassProminentButtonStyle` over custom glass for buttons.

**Motion**
- Toggle and selection: spring, quick (under 0.3s).
- Screen change: crossfade with a slight offset, no bounce.
- Batch apply: per-row progress that resolves into a checkmark or an error state.
- No animation on routine list scroll or hover-only feedback that can feel busy.

**Accessibility**
- VoiceOver labels on every toggle, with the risk level and the effect in the label.
- Keyboard navigation for everything, including the review sheet.
- Reduce Motion, Reduce Transparency, Increase Contrast, and Dynamic Type all tested.
- Minimum contrast checked on glass surfaces over a bright wallpaper and a dark one.

## 4. Information architecture

Sidebar (`NavigationSplitView`):
- **Overview**: detected Mac info, what's already applied, suggested starting profile
- **Tweaks**: categories (Privacy, Finder, Dock and Menu Bar, Performance, Developer, Security)
- **Apps**: Homebrew casks and App Store picks, grouped by category, multi-select
- **Profiles**: built-in and saved setups, import and export
- **History**: every applied change, with per-item and per-batch revert
- Settings (separate window): safety defaults, logging, update channel

Flows:
1. **First launch**: read-only scan of current settings, so the app shows the real state, not assumptions.
2. **Select, then review**: checking a tweak doesn't apply it. A floating glass bar shows the count and opens a review sheet listing every command.
3. **Apply**: runs with progress, writes a snapshot, logs to History. Partial failures are reported per item, and the rest keep going.
4. **Revert**: from History, per item or per batch.

## 5. Architecture

```
MacKit.xcodeproj
├── MacKitApp/              App target: entry point, scenes, menu commands
├── MacKitUI/               SwiftUI views, design tokens, reusable components
├── MacKitCore/             Swift package, no UI, fully unit tested
│   ├── Tweaks/             Tweak protocol, registry, categories, risk levels
│   ├── Execution/          Command runner (actor), allowlist, timeouts, dry run
│   ├── State/              Read-current-state, snapshots, history store
│   ├── Apps/               Homebrew client, App Store lookup
│   └── Profiles/           Profile model and JSON codec
└── MacKitHelper/           (v1) privileged helper for root-only changes. Swift if SMAppService works unsigned; otherwise C++.
```

**Core model**

```swift
protocol Tweak: Sendable {
    var id: TweakID { get }
    var title: String { get }
    var summary: String { get }          // one line, plain English
    var category: TweakCategory { get }
    var risk: RiskLevel { get }          // .safe, .caution, .advanced
    var requiresRestart: RestartScope?   // none, app, Finder, Dock, logout, reboot

    func currentState() async throws -> TweakState
    func plan(for desired: TweakState) -> [Command]   // pure: no side effects
    func revert(from snapshot: Snapshot) -> [Command]
}
```

- **Plan, then execute.** `plan` is a pure function that returns the exact commands. The UI shows them, and tests check them without touching the machine.
- **One executor.** Every command goes through a single `actor CommandRunner`. It has an allowlist of binaries (`defaults`, `killall`, `brew`, `mas`, `launchctl`), timeouts, and structured output. No raw shell strings.
- **Snapshot before write.** The runner records the prior value of every key it changes, so revert is exact, not a guess.
- **Restarts are explicit.** If a tweak needs Finder or Dock to restart, the review sheet says so, and the app asks before running `killall`.

**State and concurrency**
- Swift 6 language mode, strict concurrency.
- `@Observable` view models on `@MainActor`.
- Core services are actors or `Sendable` value types.
- Tweak state is read once on launch and refreshed on demand. No polling.

## 6. Safety and trust

This app changes system settings, so trust has to be earned in the UI and in the code.

- **Transparent by default.** Nothing runs without showing the command first.
- **Reversible.** Every change has a snapshot and a revert path. History survives relaunch.
- **Risk labels.** `Safe` (reversible preference, no restart), `Caution` (restarts a system UI process), `Advanced` (root, system files, or hard to undo). Advanced items are off by default and need an extra confirm.
- **No network scripts.** The app never downloads and runs code. Profiles are declarative: a list of tweak IDs and app IDs, not shell.
- **Open about what it does.** The tweak catalog lives in the repo, and each entry documents what it changes. Builds are unsigned until a Developer ID is available, so the README must explain the first-launch Gatekeeper step.
- **Logs.** A local log of every command and its exit status, exportable for bug reports. No telemetry in v1.

**Why not the App Store (v1):** the sandbox blocks the changes this app exists to make. We can revisit a limited, App Store-safe edition later if it makes sense.

## 8. Apps installer

- **Homebrew** casks and formulae as the main source. Detect whether Homebrew is installed, and offer to install it with its official instructions.
- **`mas`** for Mac App Store apps, if the user signs in to the App Store.
- Curated lists by category (Browsers, Dev, Creative, Utilities).
- Shows what is already installed. Installs run in a visible queue with per-app progress and logs.
- Never installs anything silently.

## 9. Profiles

- Built-in starting profiles, for example "Clean and private", "Developer", and "Creative".
- A profile is a JSON file: tweak IDs with desired values, app IDs, and a version.
- Export a profile to share. Import previews the changes before applying.
- Profiles reference only the catalog. An unknown ID is shown as "not supported on this macOS version" and skipped.

## 10. Testing

- **Core (Swift Testing):** `plan` output for each tweak, snapshot and revert round-trips, command allowlist rejects anything else, profile decode and version handling.
- **Fake executor:** all tests run with a fake `CommandRunner`, so no test changes real settings.
- **UI:** previews for every screen in light and dark, at default and largest Dynamic Type, with Reduce Motion on.
- **Manual:** a checklist run on a clean macOS 27 VM and on a daily-use Mac. Every tweak is applied and reverted, and the result is checked.

## 12. Decisions

1. **Minimum macOS:** macOS 27 only.
2. **Privileged changes:** included in v1. Use `SMAppService` if it works with an unsigned app. If Swift can't use those APIs, write the helper in C++.
3. **Distribution:** unsigned DMG on GitHub Releases at release time. Homebrew and other installers come later.
4. **Apple Developer account:** none yet. Signing and notarization are deferred to Phase 4.
5. **Name check:** skipped for now. "MacKit" is the working name, and conflicts (App Store, GitHub, trademarks) are unchecked.

**Open risks**
- An unsigned privileged helper may be rejected by `SMAppService`. Verify this on macOS 27.2 early in Phase 1, before building on it.
- Unsigned apps trigger Gatekeeper warnings on first launch. Homebrew casks for unsigned apps may need extra handling.
